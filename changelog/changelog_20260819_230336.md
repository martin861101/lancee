# Hermes Agent runtime integration — 2026-08-19

## Summary

WorkspaceChat now uses a provider gateway. Hermes Agent is the primary native
agent runtime when configured; the existing Lancee planner/executor is retained
as an isolated fallback. Bounded AI completion requests remain on
`completeChat()` and continue to support OpenAI, Anthropic, Gemini, and Hermes.

## Implemented

- Added `server/agents/agent-provider.mjs` for provider selection, trusted
  workspace/user context validation, status, and fallback handling.
- Added native Hermes integration in
  `server/agents/hermes-agent-provider.mjs` for sessions, runs, polling, SSE
  event metadata, approval decisions, cancellation, stable memory scoping, and
  failure persistence.
- Added `server/agents/lancee-agent-provider.mjs` as the legacy-runtime adapter.
- Routed `/api/agent/runs` and its resume, approval, and cancel endpoints
  through the gateway.
- Added `/api/agent/status` and nested agent/completion status to
  `/api/ai/status`.
- Preserved the Lancee MCP capability registry and its authenticated,
  workspace-scoped `mcp:invoke` token boundary.
- Added `npm run verify:agent` and included it in `verify:platform`.
- Updated `.env.example`, `README.md`, and `docs/HERMES.md`.

## Hermes boundary

Hermes owns reasoning and its native tool loop. Lancee owns authorization,
tenant isolation, business capability execution, approvals, durable mapping,
and audit records. Hermes MCP credentials must be configured server-side per
workspace/profile; dynamic per-request MCP credentials are not currently part
of the documented Hermes API.
