# MCP composability contract audit

## Fixed

- Reproduced the `Result 1.data.results.0.id is unavailable.` failure and traced it to the native MCP adapter forwarding raw `{ files, total }` output.
- Added a centralized result normalizer for the 42 base tools and four feature-gated OpenConnector tools.
- Native MCP and normalized agent responses now expose `success`/`ok`, `data.results`, `data.resource`, bounded errors, canonical IDs/types/names, sanitized resources, artifact metadata, and contract diagnostics.
- Preserved raw `/api/mcp/invoke`, `runtime.invoke`, and capability adapter shapes for existing UI, REST, and internal callers.
- Added MCP output schemas, audit diagnostics, cross-workspace checks, create/use and list/select/mutate coverage, and normalized error coverage.
- Updated the Codex connector verification for the canonical envelope and documented the intentional 40-to-42 catalog change.

## Documentation

- Added [`docs/LANCEE_MCP_CONTRACT_AUDIT.json`](docs/LANCEE_MCP_CONTRACT_AUDIT.json), including tool mappings, downstream chains, unsupported domain gaps, and the original failure cause.
- Updated `README.md` with the canonical result envelope and `npm run verify:mcp-contracts`.
