# MCP canonical result contract fix — 2026-08-20

## Root cause

Normalized MCP list responses exposed the same collection twice. A file search could return both `data.files` and `data.results`, which allowed Hermes to infer an invalid hybrid path such as `data.results.files[0].id`.

## Changes

- Made normalized list and dashboard responses expose one canonical collection: `data.results[]` with `data.total`.
- Kept single-resource responses on `data.resource` and preserved safe domain aliases where existing consumers require them.
- Prevented artifact list responses from duplicating `data.artifacts` beside `data.results`.
- Added `total` to the published MCP output schema.
- Added regression coverage for duplicate filenames, direct search-to-read chaining, representative project/client/invoice/workflow/job chains, normalized errors, structured content, tenant isolation, and the `/mcp` HTTP contract.
- Updated the README and machine-readable contract audit.
