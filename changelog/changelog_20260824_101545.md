# Connected Intelligence Backend Foundation — Phase 1A

Date: 2026-08-24 10:15:45 UTC

## Current architecture audited

Workspace activity is persisted as authoritative `workspace_events`. Calendar
and provider-neutral Mail records feed deterministic meeting and communication
feature calculations. `project_meeting_load` and `client_attention_load` then
upsert workspace-scoped, deduplicated `connected_opportunities`, whose evidence
references resolve back to workspace events. The existing summary/opportunity
API feeds the extracted Connected Intelligence page.

Hermes receives Lancee business capabilities through MCP. Before this change,
normal Workspace AI snapshots, prompts, routing, and MCP descriptions still
presented structured Decision Intelligence and its review queue as the current
intelligence product.

## Implemented

- Added workspace-scoped `connected_inspections` persistence, indexes, and a
  best-effort lifecycle service for start, complete, fail, list, detail, and
  summary operations.
- Instrumented non-empty incoming Mail sync batches, completed Calendar
  batches, project meeting-load detector runs, and cross-source client-attention
  detector runs. No detector threshold or feature formula changed.
- Linked detector inspections to existing created/reused opportunities without
  changing the unique deduplication key.
- Extended `GET /api/connected-intelligence/summary` with factual finding and
  inspection state while preserving its existing relationship/count payload.
- Added `GET /api/connected-intelligence/activity` and
  `GET /api/connected-intelligence/activity/:id` with bounded pagination and
  semantic, body-free responses.
- Added typed summary/activity clients in `src/lib/api.ts`; the Intelligence UI
  itself was not redesigned.
- Added MCP capabilities for Connected Intelligence summary, findings,
  activity/detail, and finding evidence. All reuse the Connected Intelligence
  service and authenticated context.
- Replaced the normal Workspace AI snapshot and prompt contract with Connected
  Intelligence and its `attention_needed`, `all_clear`, and
  `insufficient_activity` states.
- Retained structured Decision Dynamics storage, APIs, migrations, and tools
  for compatibility, but marked MCP descriptions as legacy decision history
  and restricted normal routing to explicit historical requests.

## Security and privacy

- Every inspection, summary, activity, finding, and evidence query derives the
  workspace from trusted Lancee context.
- Activity responses expose semantic count metadata only. They do not expose
  Mail bodies, provider payloads, credentials, secrets, or raw event payloads.
- Opportunity evidence resolution verifies both the finding and each event in
  the same workspace.
