# Fix Hermes file durability and conversation continuity — 2026-08-22 18:15:25 UTC

## Audit

- The ghost attachment was the persisted `art_…` provenance representation of
  a valid workspace file. WorkspaceChat preferred `artifact.id` over
  `storageDocumentId`, producing `/api/documents/art_…/download`; the canonical
  sibling `doc_…` attachment opened correctly.
- Hermes status artifacts nested under `results[].data.files[]` exceeded the
  parser's depth bound, while shallower event/tool representations were found.
  This made persistence depend on which representation arrived.
- File-reference continuity—not the normal thread/session mapping—was broken:
  files missed by parsing were not linked into authoritative conversation
  history, history used coarse artifact summaries, and Lancee exposed no
  authorized rename operation. The frontend normally returned the same thread,
  and the backend retained the same `agent_thread`, external Hermes session,
  session headers, and explicit `conversation_history`.

## Changed

- Canonicalized every openable attachment to a verified workspace document and
  stopped linking or rendering metadata-only, missing, failed-import, or
  cross-workspace artifact candidates.
- Added bounded `hermes.artifact.rejected` diagnostics without file contents,
  credentials, or private paths; successful duplicate status/event artifacts
  collapse to one file.
- Raised the bounded structured-result traversal depth enough for native
  `results[].data.files[]` envelopes.
- Reconstructed bounded per-turn history with live verified artifact ID,
  document ID, name, and MIME metadata.
- Added a synchronous WorkspaceChat thread ref alongside scoped local storage.
- Added the approved workspace-scoped `rename_file` MCP capability and kept
  linked artifact names consistent with the renamed durable document.
- Added `verify:hermes` and updated the MCP/Codex catalog count to 50.

## Schema

- No schema changes.

## Security

- Document resolution, history, artifact links, rename, and downloads remain
  scoped to the exact authenticated workspace and user/conversation boundary.
- Separate conversations and workspaces do not inherit artifact context.
- Long-term Hermes preferences remain separate from conversation history.
