# Lancee local MCP integration — 2026-08-08

## Summary

Phase 1 of the Lancee runtime MCP integration is complete. Lancee now owns one
MCP server inside this repository and serves it from the application at
`POST /mcp`. External MCP federation is no longer part of the runtime.

## Implemented

- Added an in-process JSON-RPC/MCP protocol adapter backed by the existing
  Lancee tool runtime and authenticated workspace context.
- Secured `/mcp` with Lancee device tokens carrying the `mcp:invoke` scope.
- Made the Connections and Services UI describe one always-available local
  Lancee MCP service.
- Kept browser, web, document, file, and integration functionality behind
  Lancee-owned tools and adapters rather than separate MCP peers.
- Added a focused MCP protocol verifier and updated connector and durability
  verification scripts for the local endpoint.

## Removed

- Remote MCP Grid gateway, registry, generated client, environment variables,
  package dependency, and service-activation flow.
- Basebox MCP discovery, invocation, configuration, documentation, and tests.
- Standalone MCP server commands, bearer-token configuration, and the separate
  Lancee MCP proxy plugin.
- Alternate MCP server-development plugin content and the obsolete
  `configure_mcp_service` tool.

## Documentation

- Established `LANCEE_RUNTIME_MCP_INTEGRATIONS.md` as the phased integration
  plan and recorded the single-server deployment invariant.
- Updated `README.md`, the canonical Lancee MCP guide, integration/service
  documentation, setup guidance, platform documentation, and static product
  pages to match the local-only architecture.

## Verification

- `pnpm build` — passed.
- `pnpm lint` — passed with existing storefront warnings.
- `pnpm verify:mcp` — passed.
- JavaScript syntax checks for the server, protocol adapter, and verification
  scripts — passed.
- `pnpm verify:codex-connector` and `pnpm verify:durability` could not bind a
  localhost port inside the restricted sandbox (`EPERM`). The required
  escalation was unavailable because the approval service reached its usage
  limit; this was an environment restriction, not an application assertion
  failure.
