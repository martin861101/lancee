# Changelog — 2026-08-08 13:22:52 UTC

## Lancee local MCP and agentic runtime V1

### Architecture

- Completed phases 0–5 of the V1 rollout in
  `LANCEE_RUNTIME_MCP_INTEGRATIONS.md`.
- Kept exactly one MCP endpoint, `POST /mcp`, inside the Lancee application.
- Removed runtime dependence on external MCP discovery, gateway configuration,
  per-workspace MCP service activation, and separate MCP deployment.
- Renamed the Connections catalog key from `mcp-grid` to `lancee-mcp` and
  migrated existing rows. Startup drops the obsolete `mcp_access` and
  `mcp_service_state` tables; the invocation audit ledger remains.

### Capability registry

- Expanded the dynamic public catalog to 40 Lancee-owned tools.
- Added immutable input/output contracts, role/risk/approval policy, timeouts,
  availability, cost estimates, concurrency limits, normalized envelopes,
  discovery, rate limits, and one audit hook.
- Added local web search/access/extract/crawl; file read/write/search/metadata;
  PDF/DOCX/HTML/Markdown creation and merge; browser read/snapshot/screenshot;
  visual inspection/palette; artifacts; durable jobs; approvals; and bounded
  integration adapters.
- Hardened outbound access with production HTTPS, DNS resolution and address
  pinning, private/special IPv4 and IPv6 blocking, redirect revalidation,
  sensitive-header/credential rejection, and byte/request/time limits.

### Agent runtime

- Added persisted threads, runs, steps, approvals, and sequenced events.
- Added constrained JSON planning, capability discovery, real backward-only
  result references between steps, schema validation, normalized observation,
  and final summarization from real results.
- Added hard step/tool/runtime/cost/token budgets, deterministic bounded retry,
  identical-call loop protection, cancellation, and restart-resumable state.
- Added expiring one-use approvals bound to the exact run, step, capability,
  and canonical resolved-argument hash.
- Added authenticated, idempotent start/list/get/resume/decide/cancel APIs and
  connected the floating dashboard assistant to them.

### Durable jobs and artifacts

- Added database-authoritative execution jobs with idempotent enqueue, a
  per-workspace queue ceiling, atomic claims, leases, heartbeats, recovery,
  exponential retry, cancellation, terminal failure, and durable events.
- Added artifact registration/content/listing, SHA-256 integrity, metadata,
  links, expiry, soft deletion, restoration, and workspace isolation.
- Added the new repositories and schema to both SQLite and PostgreSQL-compatible
  paths and to the SQLite-to-PostgreSQL migration inventory.

### Browser and dependencies

- Added pinned `playwright` and `sharp` production dependencies.
- Based the runtime container on the matching Playwright image and delegated
  browser work to an unprivileged `pwuser` child in the same application
  container.
- Disabled MCP Python/JavaScript execution by default in `.env.example`.

### Compatibility and verification

- Generated MCP discovery from the live registry so listed and validated
  schemas remain identical.
- Retained the existing dashboard single-tool proposal flow as a compatibility
  fallback.
- Updated connector expectations for the 40-tool catalog and required secure
  rejection of loopback HTTP web-search fixtures.
- Updated the Core/Edge review verifier to supply the required review-package
  bucket.
- Added focused verifiers for capability/security contracts, documents,
  persistence, agent execution, workers, and artifacts, and included them in
  `verify:platform`.

### Documentation

- Updated `README.md`, `docs/GETTING_STARTED.md`,
  `docs/DURABLE_FOUNDATION.md`, and `docs/LANCEE_MCP.md`.
- Added `docs/LANCEE_AGENT_RUNTIME.md` with execution, result-reference,
  approval, API, budget, recovery, and operating contracts.

### Deployment follow-up

- Source and injected-worker verification is complete. After building the
  production image, run one authenticated `browser_screenshot` against a public
  HTTPS page to confirm Chromium, fonts, sandboxing, and `pwuser` execution in
  the target deployment.
