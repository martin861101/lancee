# Lancee assistant dashboard access

Date: 2026-08-05

## Implemented

- Expanded the built-in Lancee MCP catalog from 9 to 17 tools.
- Added workspace-scoped dashboard reads for database status, projects,
  clients, invoices, drafts, automations, runs, files, connections, connector
  requests, notifications, and team members.
- Added approved actions for creating clients, projects, and text/Markdown/JSON
  files, changing project status, requesting connectors, and configuring live
  external MCP services.
- Added owner-only high-risk deletion for workspace files and automations.
- Added reusable workflow prompt templates, including bounded JSON plans of up
  to 12 permission-checked Core steps.
- Added persisted connector-request cards to the Connections tab.
- Added risk-labelled assistant approval cards with Confirm, Deny, and a
  distinct high-risk approval control.
- Kept the Codex MCP plugin catalog synchronized with the server definitions.

## PostgreSQL boundary

No third-party PostgreSQL MCP package was installed. The application already
uses the `pg` driver and its workspace-aware database adapter. The new
`query_dashboard` MCP tool exposes that adapter through a fixed resource
allowlist, so the assistant can inspect PostgreSQL-backed dashboard data without
receiving raw SQL access, connection strings, database credentials, arbitrary
schema access, or a caller-selected workspace id. The tool also works with the
local SQLite development fallback.

## Safety

- Every assistant tool call remains a proposal until explicitly approved in
  the browser.
- Unknown external MCP annotations default to the conservative high-risk UI.
- Destructive actions and unannotated external MCP tools require both explicit
  approval and workspace-owner role; deletion also requires the literal
  `DELETE` confirmation argument.
- MCP activation requires an approved gateway grant and a currently live,
  discovered service.
- Connector requests never fabricate credentials or claim an unsupported
  provider is connected.
