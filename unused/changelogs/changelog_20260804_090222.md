# Dashboard layout, routes, and resilience

Date: 2026-08-04 09:02:22 UTC

## Resolved

- Replaced dashboard-only component navigation with canonical, refresh-safe
  `/dashboard` and `/dashboard/<page>` routes.
- Added browser Back/Forward synchronization, protected deep-link sign-in,
  canonical migration for legacy `?page=` links, and safe fallback behavior for
  unknown dashboard paths.
- Routed sidebar, command palette, notification, profile, integration, client,
  analytics, workflow, and automation navigation through the same history-aware
  path.
- Preserved the desktop sidebar collapse preference and made the mobile scrim
  keyboard and screen-reader accessible.
- Prevented dashboard and top-bar overflow when workspace or page labels are
  long, while preserving the existing responsive sidebar behavior.
- Changed workspace bootstrap loading from all-or-nothing to independent settled
  requests so optional service failures do not discard healthy data.
- Added async cleanup guards to stop stale workspace bootstrap responses from
  mutating state after a session change.
- Added a top-level React error boundary with reload and dashboard recovery
  actions for unexpected render and lazy-load failures.
- Updated browser titles to reflect the active workspace page.

## Compatibility

- Existing public routes (`/`, `/signin`, `/signup`, `/signup/confirm`, and
  tokenized `/review/:id` links) remain supported.
- The production Express history fallback already serves `index.html` for
  authenticated dashboard GET routes and still leaves `/api/*` misses as JSON
  404 responses.
- Existing Files, workspace context, storage, API, and server changes present in
  the worktree were retained.
