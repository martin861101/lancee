# Lancee capability router foundation — 2026-08-08

## Summary

Started Phase 2 of `LANCEE_RUNTIME_MCP_INTEGRATIONS.md` by moving the first four
global capabilities behind a typed, application-owned capability registry.
The single Lancee `/mcp` endpoint and its public tool contracts remain stable.

## Implemented

- Added `server/capabilities/registry.mjs` with validated, immutable capability
  contracts and workspace-context enforcement.
- Added local web, file, document/PDF, and HTTP integration adapters.
- Bound `web_search`, `create_file`, `create_pdf`, and `call_external_api` to
  `web.search`, `file.write`, `pdf.create`, and
  `integration.http.request` respectively.
- Preserved workspace-owner enforcement for external API calls and translated
  adapter errors into the existing stable `MCP_*` error codes.
- Exposed capability metadata from the runtime for future planner, policy, and
  observability integration.
- Replaced the MCP-prefixed development HTTP override with the internal
  capability setting `LANCEE_CAPABILITIES_ALLOW_HTTP`.

## Safety and compatibility

- Public MCP tool names, input schemas, and result shapes are unchanged.
- File and PDF size limits and workspace-filtered storage are preserved.
- Web results remain bounded and normalized.
- HTTP integrations continue to reject redirects, credentials, sensitive
  headers, private/internal targets, oversized bodies, and oversized results.

## Verification

- Added `pnpm verify:capabilities` for contract metadata, adapters, MCP
  bindings, workspace scoping, stable results, and network safety.
- `pnpm verify:capabilities` — passed.
- `pnpm verify:mcp` — passed.
- JavaScript syntax checks for all capability modules and the migrated MCP
  runtime — passed.

## Remaining Phase 2 work

Browser read/screenshot support, visual analysis, universal artifact IDs,
expanded document operations, and additional typed provider adapters remain
pending.
