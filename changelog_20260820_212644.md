# Decision Intelligence Semantic Reality Check — 2026-08-20

## Implemented

- Frozen Phase 1 after verifying its schema and behavior against PostgreSQL
  16.14 in a guarded temporary database on the current Lancee database server.
- Added capped `decision-evidence-pack-v1` packs containing both decisions,
  language, rationale, vectors, outcomes, evidence, confounders, and relevant
  business context from trusted workspace-scoped reads.
- Added an explicit Hermes-only completion path and strict
  `hermes-decision-assessment-v1` JSON validator.
- Added the contextual comparison step and kept all metric, evidence, outcome,
  and final confidence authority inside Lancee.
- Persisted semantic status, explanation/error, contextual and comparison
  confidence, comparable status, factors, model, evidence-pack version,
  assessment version, and confidence-model version.
- Preserved structural comparisons with `semantic_status = unavailable` when
  Hermes is absent, invalid, unreachable, or timed out.
- Preserved existing workspace authorization, MCP approval, audit, and canonical
  result contracts.

## PostgreSQL result

The live deployment uses Compose service `db` (`agent-app-db-1`) running
PostgreSQL 16.14 with production database `lancee_app`. All verification runs
used separate `lancee_decision_verify_*` databases on the same server. The final
run also simulated an existing Phase 1 comparison row and confirmed the column
migration preserved it with safe defaults. No schema
compatibility fixes were needed. The temporary databases were dropped, and a
final read-only check confirmed production still had 70 public tables, zero
verifier workspaces, and zero verification databases.
